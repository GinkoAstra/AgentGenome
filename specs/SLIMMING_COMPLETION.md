结论：本轮有证据支持的缺陷修复与瘦身已完成，Codex 独立整合回归 **403 项通过，无跳过，159.21 秒**；运行代码、测试和包配置在测试前后摘要一致。独立 STS 评审发现的必须修项均已关闭。改动保留在工作区，未提交、推送或切换现有用户服务。

## 修复的行为

| 问题 | 现在的行为 | 验证 |
| --- | --- | --- |
| 一个 Backend 持续报错会阻断后续 Run | 在单个 Worker 边界记录 BackendError，其他任务继续协调 | 真实程序身份变化、多个 Run，覆盖普通协调和终态 drain |
| 直接 serve 后无法 stop | 启动/停止使用持久 Host/服务身份、目录及 PID start-time；未知身份拒绝发送信号 | 前台模块、console-script、后台启动、默认/相对目录；真实进程退出、未回收进程、身份冲突和未知 proc 状态 |
| 程序或材料变化导致已提交的停止无法执行 | 停止仍校验执行绑定，但跳过仅用于继续执行的当前代码/工具/材料检查 | Script API 取消实际完成；Pi 合成子进程在输入受损后仍被停止；active 执行继续拒绝不合格输入/身份 |
| 新停止路径在直接投递入口有遗漏 | Pi 拒绝未准备状态的新投递；Script 拒绝新程序接管旧身份的新投递 | 无材料读取/进程启动/新回调副作用；旧重复回执和停止仍可用；独立探针复验通过 |

最后一项是实现期间被独立评审发现并修复的 Backend 协议问题；没有证据表明普通外部 API 可以利用它。没有用“请求停止”代替实际观察，也没有将未知副作用变成可安全重放。

## 瘦身结果

- 删除未使用的 `Host.serve → Host._loop`，正式服务循环统一由 ApiServer 管理，Host 承担组装和单次协调。
- 三处 PID start-time 读取复用现有 spawn 模块的一个函数。
- 删除 MCP 未使用的参数转换函数。
- MCP 和客户端共用 `http_api.PUBLIC_OPERATIONS`，删除重复工具名列表。Teacher/Pi 安装入口读取共享定义时不再加载服务端 MCP SDK。

| 入口 | 导入耗时：前 → 后 | 进程峰值 RSS：前 → 后 | 加载模块数：前 → 后 |

这些是入口导入成本，不是服务稳态内存或业务执行性能。MCP SDK 仍是服务端依赖；没有宣称安装依赖已全部裁剪。

运行代码仍为 42 个文件、53 个 Python class 定义；函数定义 725 → 724，代码行数 24,549 → 24,633（含注释空行）。修复生命周期和投递缺口增加了检查，运行代码净增 84 行；以上瘦身收益由实际入口结构和加载测量体现，不用总行数下降代替验收。

## 保留的必要边界

Api 的权威提交、Scheduler 的图推进、Controller 的执行协调、Backend 的实际实例管理，以及共享 WorkerSpec 组合继续保留。本轮扫描没有找到合并这些职责或删除其校验的证据。

不同 JSON 写入的权限/持久化语义保留；仅为八行重复新增持久化抽象未采纳。包级 eager exports 的进一步懒加载暂缓，当前 client 导入成本较低；MCP 的传递依赖仍需要 jsonschema，删除一行声明不等于降低安装成本。
